## این کاتالوگ چیست؟

فهرست قابلیت‌های قابل ارائه و قابل برنامه‌ریزی است تا تیم فنی و شریک هم‌برند ببینند بعد از لایهٔ ۱ **چه چیزی** ساخته می‌شود، با چه مجوزی، و با چه برشی قابل اجرای `@ai-feature-implementation`.

- **Capability:** واحد ارائه (هدف، نقش‌ها، مجوز، پذیرش سطح محصول).
- **Slice:** واحد اجرا؛ یک User Story که در `start-prompt` مهارت پیاده‌سازی چسبانده می‌شود.
- پیاده‌سازی در حال ساخت در `ai-documents/features/<kebab>/` است، نه اینجا.

واقعیت محصول امروز: [`سند پایه پروژه (Core Brief).md`](../سند%20پایه%20پروژه%20(Core%20Brief).md).  
چشم‌انداز لایه‌ای: [`Product Vision & Evolution Roadmap.md`](../Product%20Vision%20%26%20Evolution%20Roadmap.md).  
حقوق و فقه (ارجاع، نه تکرار کامل): [`تحلیل feasibility حقوقی-رگولاتوری.md`](../تحلیل%20feasibility%20حقوقی-رگولاتوری.md).

## فرض‌های قفل‌شده

| موضوع | تصمیم |
|--------|--------|
| تابلو | بازارچهٔ **چندخریدار**؛ شریک نقدینگی و/یا امانی است، نه تنها خریدار دائمی کل بازار |
| برند | **هم‌برند** (چک‌یار + نام نهاد). وایت‌لیبل موج `W4` است |
| نهاد | **چند نهاد هم‌برند از ابتدا** (حداقل یک بانک و یک صندوق؛ قابل گسترش) |
| طرف قرارداد کاربر | **شریک**؛ بر اساس ریل: `escrow` → بانک، `principal_ledger` → صندوق |
| موج اول (`W1`) | فقط معامله با **صندوق** یا **امانی بانک**. سرمایه‌گذار ثالث روی تابلو تا تعیین چتر حقوقی همان `off_platform` می‌ماند |
| زبان | متن کارت‌ها فارسی؛ شناسه و نام پوشه kebab انگلیسی |
| نکتهٔ حقوقی | داخل همین ریپو، کوتاه، با ارجاع به تحلیل feasibility |

این کاتالوگ دامنهٔ اجرایی جاری (لایه ۱، پایلوت کنترل‌شده) را عوض نمی‌کند تا قابلیت مربوط `shipped` شود و سند پایه به‌روز گردد.

## نحوهٔ استفاده

فرآیند کامل (انتخاب برش، دروازهٔ وضعیت، Think/Build، GitFlow، ضدالگو): [`usage-guide.md`](usage-guide.md). خلاصه:

1. ارائه به شریک: این README + [`INDEX.md`](INDEX.md) + `capability.md` موج جاری.
2. اجرا: فقط برش `ready`؛ پرامپت از User Story همان فایل برش + skill `ai-feature-implementation`؛ خروجی Think در `ai-documents/features/<kebab>/`.
3. استعلام/KYC/SMS/صیاد/اعتبار/امضا/OCR چک: [`vendor-landscape.md`](vendor-landscape.md) قبل از قفل آداپتر.
4. وضعیت در YAML کارت و INDEX با هم؛ `in-build` یعنی `impl_path` پر است.

GitFlow: کار روی `feature/*` از `develop`. قرارداد API همچنان فقط [`MASTER_API_CONTRACT.md`](../development/MASTER_API_CONTRACT.md).
