# رده‌بندی کاتالوگ قابلیت

مقادیر این فایل در YAML کارت‌ها و ستون‌های [`INDEX.md`](INDEX.md) تکرار می‌شوند. مقدار جدید را اول اینجا تعریف کنید.

## شناسه

- قابلیت: `CY-NNN` (سه رقم، یکتا). پوشه: `CY-NNN-kebab-name/`
- برش: `CY-NNN-a`, `CY-NNN-b`, … فایل: `slices/CY-NNN-a-kebab.md`
- شناسه بازنشانی یا استفادهٔ مجدد نمی‌شود.

## وضعیت (`status`)

| مقدار | معنی |
|--------|------|
| `draft` | نوشته شده؛ هنوز مرور تیم/شریک نشده |
| `clarified` | فرض‌ها و مجوز این کارت با تصمیم‌های قفل‌شده هم‌خوان است؛ سؤال باز مسدودکننده ندارد |
| `ready` | حداقل یک برش با پذیرش قابل تست دارد |
| `in-build` | یک برش وارد Think/Build شده (`impl_path` پر است) |
| `shipped` | رفتار در کد است و در صورت نیاز سند پایه / قرارداد API به‌روز شده |
| `deferred` | عمداً عقب افتاده |
| `blocked` | پیش‌نیاز فنی، شریک، یا حقوقی ندارد |

قابلیت بدون برش از `draft` بالاتر نمی‌رود مگر اینکه صریحاً «فقط مرجع، بدون اجرا» علامت خورده باشد.

## موج (`wave`)

| موج | تمرکز |
|-----|--------|
| `W0` | پیش‌نیاز لایه ۱ که برای ریل شریک لازم است (KYC زنده، استعلام صیاد، اعتبار صادرکننده) — هنوز امانی/principal نیست |
| `W1` | هم‌برند چندنهادی؛ معامله فقط با صندوق یا امانی بانک؛ ثالث = `off_platform` |
| `W2` | چتر حقوقی سرمایه‌گذار ثالث؛ امانی برای معاملهٔ ثالث؛ قیمت‌گذاری و نکول |
| `W3` | فاکتور / SCF، بازار ثانویه، خزانه‌داری و حسابداری |
| `W4` | وایت‌لیبل، محصول داده، API باز شریک |

موج تقویم نیست؛ با آمادگی شریک جابه‌جا می‌شود.

## ریل تسویه (`settlement_rail`)

مطابق `doion.matching.constants.SettlementType`:

- `off_platform`
- `escrow`
- `principal_ledger`
- `n/a` — قابلیت پول جابه‌جا نمی‌کند

## مجوز (`license`) و کانال (`license_channel`)

`license`: `none-layer1` | `partner-covers` | `additional-permit` | `unknown`

`license_channel`:

| مقدار | معنی |
|--------|------|
| `listing_only` | کشف و آگهی؛ معامله روی پلتفرم اجرا نمی‌شود |
| `partner_trade` | طرف معامله صندوق یا امانی بانک است |
| `third_party_trade` | خریدار سرمایه‌گذار ثالث روی تابلو است |
| `mixed` | بیش از یک کانال |

در `W1` برای معاملهٔ اجراشده فقط `partner_trade` مجاز است. `third_party_trade` تا `CY-009` `blocked` است.

## برند و نقش شریک

`brand_mode`: `cobrand` (پیش‌فرض کاتالوگ) | `chequeyar` | `white_label`

`partner_roles` (لیست): `escrow_bank` | `liquidity_fund` | `both` — در عمل هر کارت زیرمجموعه می‌گیرد نه لزوماً هر دو.

طرف قرارداد در هم‌برند: شخص حقوقی **شریک** است. نگاشت ریل: `escrow` → بانک، `principal_ledger` → صندوق. چند نهاد یعنی چند tenant هم‌برند (چند بانک و/یا چند صندوق)، نه یک برند واحد اجباری.

## دامنه فنی (`domain`)

`identity` | `checks` | `marketplace` | `matching` | `pricing` | `moderation` | `notifications` | `compliance` | `integrations` | `platform`

اگر قابلیت یا برش به استعلام هویت، KYB، بیومتریک، SMS، صیاد، اعتبار صادرکننده، امضای دیجیتال، یا OCR تصویر چک وصل می‌شود، قبل از Think/Build فایل [`vendor-landscape.md`](vendor-landscape.md) اجباری است. کاندید vendor را در کارت تکرار نکنید؛ فقط ارجاع بدهید.

چرخهٔ اجرا و دروازه‌های وضعیت: [`usage-guide.md`](usage-guide.md).

## قوانین INDEX

- هر تغییر `status` / `blocked_by` / `impl_path` در YAML و در [`INDEX.md`](INDEX.md).
- `in-build` بدون لینک `ai-documents/features/...` ممنوع است.
- نکتهٔ حقوقی در کارت کوتاه است؛ متن تفصیلی در [`تحلیل feasibility حقوقی-رگولاتوری.md`](../تحلیل%20feasibility%20حقوقی-رگولاتوری.md) یا پروندهٔ شریک با نام سند در بخش ارجاع.
