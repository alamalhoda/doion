# CY-012 — نکول، وصول و ضمانت

## ۱. معرفی و هدف

پس از سررسید: ثبت نکول، مسیر وصول (عملیاتی/حقوقی با شریک)، و در صورت وجود محصول ضمانت یا بیمه از نهاد دارای مجوز — نه تضمین پلتفرم.

**شاخص موفقیت:** هیچ معاملهٔ principal/escrow بدون وضعیت پس از سررسید در «خلاء» نماند.

## ۲. مجوز و فقه

- ضمانت وصول می‌تواند ماهیت بیمه/تضمین داشته باشد → مجوز جدا (بیمه مرکزی یا بانک). `additional-permit`.
- پلتفرم ضامن نمی‌شود.
- فقه: ضمانت معاوضی با «سود قطعی سرمایه‌گذار ثالث» قاطی نشود.

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | در principal معمولاً خارج است اگر مالکیت منتقل شده | |
| صندوق / بانک | وصول، بیمه، تصمیم حقوقی | |
| پلتفرم | وضعیت، اعلان، پروندهٔ سند | پرداخت خسارت از جیب خود |

## ۴. نیازمندی‌ها و پیش‌نیازها

- معاملهٔ W1 واقعی؛ job انقضای listing موجود می‌تواند الگو باشد.
- NFR: مهلت‌ها در سرور.

## ۵. جای این قابلیت روی محصول فعلی

وضعیت Match پس از `settled` امروز ته خط است. این کارت پس از سررسید را باز می‌کند.

## ۶. سناریو

### کاربر

صندوق وضعیت «برگشت / در وصول / مختومه» را می‌بیند.

### پلتفرم

با job سررسید وضعیت را عوض می‌کند؛ به آداپتر نهاد رویداد می‌دهد.

### سناریوهای شکست

اختلاف بانک و صندوق در وصول → وضعیت `disputed`.

## ۷. شرایط پذیرش

- [ ] پلتفرم در API فیلد «تضمین چک‌یار» ندارد.
- [ ] هر ریل شریک پس از due_date وضعیت پس از سررسید دارد.
- [ ] محصول ضمانت فقط اگر نهاد ضامن روی رکورد باشد نمایش داده می‌شود.

## ۸. رول‌اوت و کنترل

فلگ `post_maturity_workflow`. ضمانت جدا `guarantee_product_enabled`.

## ۹. خارج از محدوده
