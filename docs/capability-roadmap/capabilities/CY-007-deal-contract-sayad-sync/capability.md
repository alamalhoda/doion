# CY-007 — قرارداد معامله و همگام‌سازی وضعیت صیاد

## ۱. معرفی و هدف

هر معاملهٔ ریل شریک یک بستهٔ قراردادی (شرایط، طرف حقوقی بانک یا صندوق، دیسکلیمر) و یک ماشین‌حالت **وضعیت ظهرنویسی/ثبت صیاد** دارد. پلتفرم انتقال را در صیاد انجام نمی‌دهد؛ وضعیت را از کاربر و در صورت وجود از کانال بانک همگام می‌کند تا امانی/پرداخت روی شرط درست آزاد شود.

**شاخص موفقیت:** سهم معامله‌هایی که آزادسازی وجه بدون ثبت وضعیت صیاد «منتقل‌شده» رخ نداده (باید نزدیک ۱۰۰٪ در پایلوت باشد).

## ۲. مجوز و فقه

- قرارداد به نام شریک ریل است (بانک یا صندوق).
- ثبت صیاد الزام قانونی انتقال چک است؛ پلتفرم جایگزین سامانه نیست. ارجاع: تحلیل حقوقی بخش صیاد.
- فقه: متن قرارداد باید با نظر فقهی شریک هم‌خوان باشد (خرید دین، نه وعدهٔ بهرهٔ پلتفرم).

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | در صیاد عمل می‌کند؛ در پلتفرم وضعیت را تأیید/آپلود می‌کند | انتظار انتقال توسط چک‌یار |
| سرمایه‌گذار ثالث | در W1 این بسته را برای ریل شریک ندارد | |
| بانک شریک | ممکن است وضعیت ثبت را استعلام کند | |
| صندوق شریک | ذی‌نفع انتقال به‌نام خود یا نماینده | |
| پلتفرم | قالب قرارداد، امضا/پذیرش، ماشین‌حالت، گیت آزادسازی | اجرای صیاد |

## ۴. نیازمندی‌ها و پیش‌نیازها

- ریل‌های `CY-005`/`CY-006` برای معنا داشتن گیت.
- فنی: اسناد `doion.documents`؛ رویدادهای matching.
- شریک: قالب PDF/HTML حقوقی؛ آیا امضای الکترونیک لازم است یا پذیرش درون‌برنامه کافی است. کاندید بازار: [`vendor-landscape.md`](../../vendor-landscape.md) بخش ۲.۷.
- NFR: نسخهٔ قالب قرارداد immutable پس از accept.

## ۵. جای این قابلیت روی محصول فعلی

امروز تسویه با `confirm-off-platform` و disclaimer است. این کارت برای ریل شریک جایگزین تأیید تهی می‌شود. UI: صفحهٔ معامله با چک‌لیست صیاد.

## ۶. سناریو

### کاربر

پس از قبول پیشنهاد، متن قرارداد نهاد را می‌پذیرد، مراحل صیاد را تیک می‌زند یا رسید بارگذاری می‌کند، منتظر تأیید طرف مقابل/بانک می‌ماند.

### پلتفرم

نسخهٔ قرارداد را قفل می‌کند؛ گذار صیاد را به Port امانی/صندوق می‌دهد؛ بدون وضعیت مجاز، آزادسازی را رد می‌کند.

### سناریوهای شکست

طرفین در وضعیت صیاد اختلاف دارند؛ مدرک ناخوانا؛ رد ثبت بانکی. مسیر اختلاف به عملیات دستی با کد `blocked_ops` می‌رود نه آزادسازی خودکار.

## ۷. شرایط پذیرش

- [ ] هیچ آزادسازی escrow/پرداخت principal بدون وضعیت صیاد تعریف‌شده در پیکربندی آن نهاد رخ نمی‌دهد.
- [ ] قالب قرارداد پس از پذیرش تغییر نمی‌کند؛ نسخه در audit است.
- [ ] UI و API ادعای «انتقال توسط پلتفرم» ندارند.
- [ ] مسیر `off_platform` لایه ۱ بدون این چک‌لیست اجباری می‌ماند.

## ۸. رول‌اوت و کنترل

فلگ `deal_contract_required` per rail. قطع استعلام بانک: تأیید دستی دوطرفه طبق سیاست نهاد.

## ۹. خارج از محدوده

پیام‌رسان آزاد چت. PKI اگر شریک نخواهد در پایلوت اجرا نمی‌شود اما کارت جدا است (`CY-007-c`) نه «برای همیشه خارج».
