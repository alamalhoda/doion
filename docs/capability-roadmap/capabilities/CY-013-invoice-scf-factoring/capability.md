# CY-013 — فکتورینگ فاکتور و تأمین مالی زنجیره

## ۱. معرفی و هدف

گسترش دارایی از چک به فاکتور تأییدشده و SCF (تأیید خریدار بزرگ). همان هویت، نهاد، و Port؛ مدل آگهی تعمیم می‌یابد.

**شاخص موفقیت:** اولین پایلوت فاکتور با همان صندوق بدون فورک محصول چک.

## ۲. مجوز و فقه

- فکتورینگ ذیل مجوز صندوق/نهاد. پلتفرم مالک دین نمی‌شود مگر ریل principal نهاد.
- فقه: خرید دین ناشی از بیع واقعی (فاکتور) معمولاً نزدیک‌تر به مسیر مشروع است تا چک بی‌پشتوانه؛ همچنان نظر شریک لازم است.

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| تأمین‌کننده | فاکتور را ثبت می‌کند | |
| خریدار بزرگ | تأیید دین (SCF) | |
| صندوق | خرید دین | |
| پلتفرم | آگهی/مطالبهٔ غیرچک | تبدیل شدن به ERP |

## ۴. نیازمندی‌ها و پیش‌نیازها

- تعمیم `ChequeListing` یا موجودیت `Receivable` — تصمیم طراحی در spec برش، نه اینجا.
- NFR: یکتایی فاکتور (فروشنده، شماره، خریدار).

## ۵. جای این قابلیت روی محصول فعلی

بازارچه امروز فقط چک است. فیلتر نوع دارایی اضافه می‌شود.

## ۶. سناریو

### کاربر

تأمین‌کننده فاکتور تأییدشده را می‌گذارد؛ صندوق می‌خرد.

### پلتفرم

نوع دارایی را از چک جدا نگه می‌دارد تا validation صیاد روی فاکتور اعمال نشود.

### سناریوهای شکست

فاکتور بدون تأیید خریدار در مسیر SCF منتشر نمی‌شود.

## ۷. شرایط پذیرش

- [ ] آگهی فاکتور مسیر استعلام صیاد چک را صدا نمی‌زند.
- [ ] صندوق می‌تواند همان ریل principal را روی فاکتور استفاده کند.
- [ ] بازارچه فیلتر نوع دارایی دارد.

## ۸. رول‌اوت و کنترل

فلگ `receivable_type_invoice`.

## ۹. خارج از محدوده

حسابداری کامل شرکت؛ چک برگشتی به‌عنوان فاکتور.
