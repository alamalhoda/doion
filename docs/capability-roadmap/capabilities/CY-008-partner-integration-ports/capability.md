# CY-008 — درگاه یکپارچه‌سازی بانک و صندوق

## ۱. معرفی و هدف

آداپتر پایدار برای چند نهاد: دستور امانی، وضعیت پرداخت، (اختیاری) استعلام، وب‌هوک. هر بانک و هر صندوق پیاده‌سازی جدا پشت یک Port داخلی است تا `CY-005`/`CY-006` به یک vendor قفل نشوند.

**شاخص موفقیت:** افزودن نهاد دوم بدون تغییر دامنهٔ matching؛ فقط بستهٔ آداپتر جدید.

## ۲. مجوز و فقه

- اتصال فنی مجوز نمی‌سازد؛ فقط کانال نهاد مجاز را حمل می‌کند.
- secret و گواهی متعلق به نهاد است؛ پلتفرم پردازنده است.
- فقه: N/A مستقیم. امنیت داده ذیل قرارداد شریک.

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده / سرمایه‌گذار | چیزی از آداپتر نمی‌بیند جز وضعیت ترجمه‌شده | |
| بانک / صندوق | API خود را می‌دهند | تغییر مدل دامنه چک‌یار |
| پلتفرم | Port، صف، retry، امضای وب‌هوک | منطق کسب‌وکار فقط داخل آداپتر |

## ۴. نیازمندی‌ها و پیش‌نیازها

- `CY-003` (شناسه نهاد).
- فنی: الگوی موجود `doion.integrations` (SMS stub).
- شریک: OpenAPI یا مستند وب‌هوک؛ محیط sandbox.
- NFR: timeout، idempotency key، DLQ، بدون PII اضافه در لاگ.

## ۵. جای این قابلیت روی محصول فعلی

امروز SMS stub. این کارت همان app را گسترش می‌دهد. UI ندارد مگر صفحهٔ ادمین سلامت آداپتر.

## ۶. سناریو

### کاربر

غیرمستقیم: وضعیت معامله به‌روز می‌شود.

### پلتفرم

دستور دامنه به Port؛ آداپتر HTTP؛ وب‌هوک ورودی با `institution_id` و امضا.

### سناریوهای شکست

امضای نامعتبر → 401 و alert. retry تمام‌شده → وضعیت `integration_failed` روی معامله.

## ۷. شرایط پذیرش

- [ ] دامنهٔ matching به URL خام بانک وابسته نیست.
- [ ] می‌توان آداپتر دوم را بدون migration دامنه اضافه کرد.
- [ ] وب‌هوک نهاد A معاملهٔ نهاد B را تغییر نمی‌دهد.
- [ ] تست‌ها با stub بدون شبکهٔ واقعی سبز می‌مانند.

## ۸. رول‌اوت و کنترل

فلگ per-institution `integration_live`. پیش‌فرض sandbox/stub. کلید خاموش: توقف دستورات جدید.

## ۹. خارج از محدوده

پیاده‌سازی واقعی هر بانک قبل از قرارداد؛ Open Banking عمومی.
