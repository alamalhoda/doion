# CY-003 — هم‌برند چندنهادی

## ۱. معرفی و هدف

پلتفرم از روز اول باید چند نهاد هم‌برند را مدل کند: حداقل یک بانک (امانی) و یک صندوق (خرید دین)، قابل افزایش. کاربر نام چک‌یار و نام نهاد مرتبط با آن معامله یا آن حساب را می‌بیند. این قابلیت پول جابه‌جا نمی‌کند؛ هویت سازمانی و پوستهٔ برند را می‌سازد.

**شاخص موفقیت:** پایلوت با بیش از یک نهاد بدون شاخه‌کردن کد به‌ازای هر شریک؛ انتخاب نهاد روی آگهی/معامله مشخص و قابل audit است.

## ۲. مجوز و فقه

- خودِ مدل tenant مجوز بانکی نیست؛ هر نهاد مجوز خودش را دارد.
- کانال: `mixed` — زیرساخت همهٔ کانال‌ها.
- برند: `cobrand`. وایت‌لیبل خارج از محدوده (`CY-016`).
- طرف قرارداد معامله در کارت‌های ریل تعریف می‌شود؛ اینجا فقط مشخص می‌شود کدام شخص حقوقی روی UI و فوتر کدام زمینه است.
- فقه: معرفی چند نهاد واسطهٔ تنزیل ثالث را به‌خودی‌خود حل نمی‌کند. ارجاع: تحلیل حقوقی (واسطه، ماده ۵۹۵) و فرض قفل‌شدهٔ W1 در [`README.md`](../../README.md).

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | نهاد امانی یا خریدار نهادی را مطابق قوانین Match می‌بیند | تعریف حقوقی نهاد |
| سرمایه‌گذار بازارچه | می‌فهمد آیا طرف معامله شریک است یا هنوز off-platform | تغییر برند پلتفرم |
| بانک شریک | به‌عنوان `Institution` با نقش `escrow_bank` ثبت می‌شود | الزام تنها بانک بودن کل سامانه |
| صندوق شریک | به‌عنوان `Institution` با نقش `liquidity_fund` | امانی به‌جای بانک مگر نقش جدا داشته باشد |
| پلتفرم | کاتالوگ نهاد، تم هم‌برند، فلگ per-institution | ادعای مجوز نهاد |

## ۴. نیازمندی‌ها و پیش‌نیازها

- محصولی: نقش‌های کاربر فعلی کافی است؛ نقش «نهاد» جدا از `investor` است.
- فنی: مدل نهاد، عضویت، کلید پیکربندی تم/لوگو، بدون hard-code نام بانک.
- شریک: شناسه حقوقی، لوگو، متن دیسکلیمر، محیط API جدا per institution.
- NFR: جداسازی تنظیمات و secret per institution؛ عدم نشت دادهٔ یک نهاد به پنل نهاد دیگر.

## ۵. جای این قابلیت روی محصول فعلی

لایه ۱ تک‌مستأجر ضمنی است. این کارت platform است: روی همهٔ صفحات احرازشده و لندینگ (نشان هم‌برند) اثر می‌گذارد. Feature Flag `cobrand_institutions_enabled`.

## ۶. سناریو

### کاربر

کاربر واردشده روی هدر/فوتر چک‌یار + نهاد(های) فعال را می‌بیند. در جریان معامله فقط نهاد همان ریل نمایش داده می‌شود.

### پلتفرم

درخواست‌ها `institution_id` دارند جایی که معامله یا امانی معنا دارد. ادمین نهاد را CRUD می‌کند (جنگو ادمین در برش اول کافی است).

### سناریوهای شکست

نهاد غیرفعال است → ریل آن نهاد در UI انتخاب‌شدنی نیست. لوگو نیست → نام حقوقی کافی است.

## ۷. شرایط پذیرش

- [ ] می‌توان حداقل دو نهاد (یک بانک، یک صندوق) همزمان فعال داشت.
- [ ] تنظیمات و secret یک نهاد در پاسخ API نهاد دیگر نمی‌آید.
- [ ] با فلگ خاموش، UI و API رفتار تک‌برند لایه ۱ را حفظ می‌کنند.
- [ ] متن قانونی صفحه حداقل نام چک‌یار و نام شخص حقوقی نهاد مرتبط را دارد.

## ۸. رول‌اوت و کنترل

فعال‌سازی per institution. خاموش کردن یک نهاد معاملات جدید آن نهاد را می‌بندد؛ معاملات باز سیاست جدا (`CY-005`/`CY-006`).

## ۹. خارج از محدوده

وایت‌لیبل کامل، امانی واقعی، دفتر principal، دروازهٔ طرف معامله (`CY-004`).
