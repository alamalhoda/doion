# CY-004 — دروازهٔ طرف معامله در موج اول

## ۱. معرفی و هدف

تابلو چندخریدار می‌ماند، اما **اجرای معامله روی ریل شریک** در W1 فقط با صندوق (خرید) یا امانی بانک است. سرمایه‌گذار ثالث می‌تواند آگهی ببیند و طبق لایه ۱ `off_platform` ابراز تمایل کند؛ نمی‌تواند تا `CY-009` وارد `escrow` یا `principal_ledger` شود.

**شاخص موفقیت:** در پایلوت W1 هیچ Match با `settlement_type` غیر `off_platform` که طرف آن نهاد ثبت‌شده نباشد ایجاد نشود.

## ۲. مجوز و فقه

- پوشش مجوز شریک فقط کانال `partner_trade` است.
- ثالث روی تابلو = کانال کشف + تسویه بیرون؛ همان ریسک لایه ۱ برای آن Match باقی است — آگاهانه تا چتر حقوقی.
- برند هم‌برند روی معاملهٔ شریک؛ روی Match ثالث دیسکلیمر لایه ۱.
- فقه/حقوق: تحلیل feasibility دربارهٔ واسطه و P2P؛ این دروازه ریسک کانال ثالث را با نبردن آن به امانی/principal کم می‌کند نه اینکه ریسک لایه ۱ را صفر کند. ارجاع: همان تحلیل + فرض W1 در README کاتالوگ.

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | پیشنهاد صندوق یا مسیر امانی بانک را از پیشنهاد ثالث تشخیص می‌دهد | اجبار به پذیرش شریک |
| سرمایه‌گذار بازارچه | Browse و Match با `off_platform` | انتخاب escrow/principal |
| بانک شریک | فقط اگر مسیر امانی انتخاب شود (کارت بعد) | خریدار بودن صرفاً به‌خاطر این دروازه |
| صندوق شریک | می‌تواند طرف `principal_ledger` باشد | دور زدن دروازه |
| پلتفرم | enforce سمت API و UI | اجرای تسویه |

## ۴. نیازمندی‌ها و پیش‌نیازها

- `CY-003` برای شناخت نهاد.
- فنی: `doion.matching`، `SettlementType`، Feature Flag.
- شریک: فهرست نهادهای مجاز برای هر ریل.
- NFR: رد API با کد صریح نه فقط مخفی کردن دکمه.

## ۵. جای این قابلیت روی محصول فعلی

`POST /api/v1/matches/` امروز هر سرمایه‌گذار تأییدشده را می‌پذیرد. این کارت قانون طرف و `settlement_type` را اضافه می‌کند. UI: مودال بازارچه و جزئیات Match.

## ۶. سناریو

### کاربر

سرمایه‌گذار حقیقی ثالث «ابراز تمایل» می‌زند → Match با `off_platform`. صندوق (نهاد) مسیر خرید سازمانی را می‌زند → ریل `principal_ledger` فقط اگر فلگ و نهاد فعال باشد.

### پلتفرم

اگر کاربر غیرنهاد `settlement_type=escrow` بفرستد → خطا. اگر نهاد صندوق `off_platform` بخواهد، سیاست پایلوت را اعمال می‌کند (ترجیح: صندوق فقط ریل خودش).

### سناریوهای شکست

نهاد صندوق غیرفعال → مسیر principal بسته. دور زدن UI با API خام → همان خطا.

## ۷. شرایط پذیرش

- [ ] کاربر با نقش سرمایه‌گذار غیرنهاد نمی‌تواند Match با `escrow` یا `principal_ledger` بسازد.
- [ ] نهاد با نقش `liquidity_fund` می‌تواند مسیر principal را شروع کند (جزئیات اجرا در `CY-006`).
- [ ] سرمایه‌گذار ثالث همچنان می‌تواند Match لایه ۱ با `off_platform` بسازد مگر فلگ جدا آن را ببندد.
- [ ] رویداد audit دلیل رد ریل را ثبت می‌کند.

## ۸. رول‌اوت و کنترل

فلگ `partner_rails_enabled`. خاموش = فقط `off_platform` مثل امروز. پس از `CY-009` این دروازه باید شل شود نه اینکه کد دور ریخته شود (قانون قابل پیکربندی).

## ۹. خارج از محدوده
