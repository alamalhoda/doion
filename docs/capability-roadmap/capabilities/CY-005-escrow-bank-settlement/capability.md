# CY-005 — ریل امانی بانک

## ۱. معرفی و هدف

پیاده‌سازی `settlement_type=escrow` روی `SettlementPort`: وجه سرمایه‌گذارِ مجاز (در W1: مسیر متصل به نهاد بانک، نه ثالث آزاد) نزد بانک هم‌برند قفل می‌شود تا شرایط توافق و ثبت صیاد محقق شود، سپس آزاد یا برمی‌گردد.

**شاخص موفقیت:** تعداد معاملهٔ امانی که از قفل تا آزادسازی یا بازگشت بدون مداخلهٔ دستی خارج از ماشین‌حالت به پایان می‌رسند.

## ۲. مجوز و فقه

- نگهداری وجه شخص ثالث: پوشش **مجوز بانک** هم‌برند؛ پلتفرم حساب امانی باز نمی‌کند.
- طرف قرارداد کاربر برای این ریل: **بانک**.
- کانال W1: `partner_trade`. ثالث وارد این ریل نمی‌شود (`CY-004` + `CY-010` بعداً).
- فقه: ساختار باید خرید دین/امانی مشروع باشد نه وعدهٔ سود قطعی. ارجاع: لایه ۲ در Product Vision و تحلیل حقوقی (خدمات پرداخت / نگهداری وجه).

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | شرایط آزادسازی را می‌پذیرد؛ وجه را پس از آزادسازی می‌گیرد | کنترل حساب امانی بانک |
| سرمایه‌گذار بازارچه | در W1 وارد این ریل نمی‌شود | |
| بانک شریک | افتتاح/مسدود حساب امانی، گزارش وضعیت، آزادسازی طبق دستور مجاز | قیمت‌گذاری تنزیل الزام‌آور پلتفرم |
| صندوق شریک | اگر خریدار باشد ممکن است وجه را به امانی بانک واریز کند | خودش امانی‌دار بودن مگر نقش بانک داشته باشد |
| پلتفرم | ماشین‌حالت، دستورات به Port بانک، UI وضعیت | نگهداری موجودی |

## ۴. نیازمندی‌ها و پیش‌نیازها

- `CY-003`، `CY-004`؛ هم‌مسیر با `CY-007` (صیاد) و `CY-008` (آداپتر).
- فنی: گسترش `SettlementPort` در `doion.matching`؛ مقادیر رزروشده از قبل در constants.
- شریک: حساب عملیاتی، وب‌هوک وضعیت، محیط تست.
- NFR: idempotency دستور آزادسازی؛ audit کامل مبالغ و شناسهٔ بانک؛ هیچ secret در ریپو.

## ۵. جای این قابلیت روی محصول فعلی

امروز فقط `OffPlatformSettlement` و `confirm-off-platform`. این کارت پیاده‌سازی Port برای escrow است نه بازنویسی `ChequeListing`. UI: جزئیات Match + وضعیت امانی.

## ۶. سناریو

### کاربر

دارنده و طرف مجاز مسیر «تسویه امانی بانک X» را انتخاب می‌کنند، شناسهٔ واریز می‌بینند، وضعیت «قفل / آزاد / برگشت» را دنبال می‌کنند.

### پلتفرم

Match را `escrow` می‌کند، به آداپتر بانک دستور می‌دهد، وب‌هوک را با امضای نهاد راستی‌آزمایی می‌کند، وضعیت را به دو طرف نشان می‌دهد.

### سناریوهای شکست

واریز ناقص؛ رد صیاد پس از قفل؛ timeout وب‌هوک؛ دستور آزادسازی تکراری. در همه: وضعیت صریح + بدون آزادسازی دوبارهٔ وجه.

## ۷. شرایط پذیرش

- [ ] Match با `escrow` بدون `institution` بانک معتبر ساخته نمی‌شود.
- [ ] پلتفرم موجودی را در دفتر خودش به‌عنوان منبع حقیقت پول نگه نمی‌دارد؛ منبع وضعیت بانک است.
- [ ] آزادسازی و بازگشت فقط از گذارهای تعریف‌شده و با audit است.
- [ ] فلگ خاموش مسیر escrow را از API حذف می‌کند.

## ۸. رول‌اوت و کنترل

فلگ `escrow_rail_enabled` و فلگ per-bank. قطع API بانک: وضعیت «نامشخص»؛ آزادسازی خودکار ممنوع. کلید خاموش: معاملات جدید escrow بسته؛ بازها دستی عملیاتی با بانک.

## ۹. خارج از محدوده

ضمانت وصول (`CY-012`)، امانی برای ثالث (`CY-010`)، principal صندوق (`CY-006`).
