# CY-019 — استعلام اعتبار صادرکننده و سابقهٔ چک

## ۱. معرفی و هدف

KYC کاربر (`CY-001`) می‌گوید آگهی‌دهنده کیست. کیفیت آگهی و سقف خرید صندوق به **صادرکنندهٔ چک** بستگی دارد: برگشتی، تسهیلات، رنگ/اعتبار معاملاتی، زنجیرهٔ چک — جدا از وضعیت همین برگه در صیاد (`CY-002`).

لایه ۱ امروز ریسک را از خوداظهاری و ناظر می‌گیرد. تحلیل حقوقی می‌گوید دسترسی به سامانهٔ ملی اعتبارسنجی معمولاً مال نهاد مجاز است؛ پلتفرم رتبهٔ رسمی نمی‌فروشد.

**شاخص موفقیت:** سهم آگهی‌هایی که ناظر یا میز صندوق با استناد به استعلام صادرکننده رد یا سقف می‌گذارد، نسبت به رد سلیقه‌ای.

## ۲. مجوز و فقه

- استعلام اعتباری اشخاص اغلب نیازمند کانال بانک/مؤسسهٔ مجاز یا واسط با مجوز است → `partner-covers`.
- کانال W0: `listing_only` — نتیجه برای moderation و صندوق؛ **نمایش نمره به سرمایه‌گذار ثالث در W1 ممنوع است** مگر شریک صریح بگوید (`CY-011`).
- پلتفرم bureau نیست و «رتبهٔ اعتباری چک‌یار» نمی‌سازد.
- فقه: دادهٔ ریسک موضوع ربا نیست؛ ادبیات UI نباید سود قطعی القا کند. ارجاع: تحلیل feasibility (رتبه‌بندی اعتباری و محدودیت دسترسی).

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | رضایت استعلام صادرکننده را در حد قانون/قرارداد می‌دهد | دیدن نمرهٔ خام bureau مگر سیاست بگوید |
| سرمایه‌گذار ثالث | در W1 نمرهٔ رسمی نمی‌بیند | تصمیم صرفاً بر اساس «امتیاز پلتفرم» |
| بانک شریک | کانال استعلام یا تأیید دسترسی | |
| صندوق شریک | مصرف‌کنندهٔ اصلی برای سقف خرید | |
| پلتفرم | فراخوانی، کش کوتاه، ضمیمه به آگهی/ناظر | فروش رتبه |

## ۴. نیازمندی‌ها و پیش‌نیازها

- محصولی: ایجاد آگهی و moderation؛ Feature Flag.
- فنی: Port جدا از KYC و جدا از استعلام شناسهٔ صیادی همین چک.
- شریک: قرارداد bureau/واسط طبق [`vendor-landscape.md`](../../vendor-landscape.md) بخش ۲.۶؛ رضایت سوژه در صورت الزام تأمین‌کننده.
- NFR: حداقل نگهداری؛ عدم لاگ ریزگزارش اعتباری.

## ۵. جای این قابلیت روی محصول فعلی

اعتبارسنجی اضافی روی جریان آگهی یا پنل ناظر/صندوق. `doion.pricing` stub را عوض نمی‌کند؛ ورودی اختیاری برای `CY-011` است.

## ۶. سناریو

### کاربر

دارنده آگهی می‌سازد. ناظر سابقهٔ صادرکننده را کنار تصویر چک می‌بیند. صندوق در W1 همان خلاصه را در میز خرید می‌بیند.

### پلتفرم

پس از ثبت یا هنگام moderation استعلام شخص صادرکننده را می‌زند؛ نتیجه را به تصمیم ضمیمه می‌کند؛ به marketplace عمومی نمره نمی‌دهد.

### سناریوهای شکست

قطع bureau → آگهی در صف با برچسب «استعلام اعتبار ناموفق»؛ انتشار خودکار بر اساس نمرهٔ قدیمی ممنوع.

## ۷. شرایط پذیرش

- [ ] API عمومی آگهی فیلد نمرهٔ bureau برای مهمان/ثالث ندارد مگر فلگ جدا و تأیید شریک.
- [ ] شکست تأمین‌کننده `approved` آگهی نمی‌سازد.
- [ ] با فلگ خاموش، لایه ۱ بدون این استعلام کار می‌کند.
- [ ] متن UI «رتبهٔ رسمی» یا «سود تضمینی» ندارد.

## ۸. رول‌اوت و کنترل

فلگ `issuer_credit_inquiry_enabled`. خاموش = رفتار فعلی. کلید قطع = فقط moderation دستی.

## ۹. خارج از محدوده

KYC کاربر (`CY-001`)، استعلام شناسه/وضعیت **همین** چک (`CY-002`)، کمک OCR ورود آگهی (`CY-020`)، موتور قیمت (`CY-011`)، محصول دادهٔ بازار (`CY-017`).
