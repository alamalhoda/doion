# CY-002 — استعلام وضعیت چک صیادی

## ۱. معرفی و هدف

ثبت آگهی امروز به شمارهٔ صیادی و moderation دستی متکی است. استعلام وضعیت (اعتبار چک، در حد دسترسی قانونی پلتفرم یا شریک) کیفیت آگهی را بالا می‌برد و تقلب را کم می‌کند، بدون اینکه پلتفرم ظهرنویسی کند.

**شاخص موفقیت:** سهم آگهی‌های ردشده به‌خاطر ناسازگاری استعلام نسبت به رد سلیقه‌ای ناظر؛ هدف افزایش ردهای مستند است.

## ۲. مجوز و فقه

- استعلام عمومی/شریک معمولاً مجوز تنزیل نمی‌خواهد؛ دسترسی به سامانه‌های بانک مرکزی اغلب محدود به نهاد مجاز است.
- کانال: `listing_only`. این قابلیت انتقال مالکیت نیست.
- اگر استعلام فقط از کانال بانک هم‌برند ممکن است، پلتفرم عامل فنی بانک است نه دارندهٔ دسترسی مستقل.
- فقه: استعلام وضعیت دین موضوع ربا نیست. ارجاع: محدودیت عملیاتی صیاد در تحلیل حقوقی — انتقال فقط در صیاد؛ پلتفرم نباید ادعای انتقال کند.

## ۳. بازیگران و تقسیم نقش

| بازیگر | در این قابلیت چه می‌کند | چه نمی‌کند |
|--------|-------------------------|------------|
| دارنده | شماره و تصویر چک را می‌دهد | استعلام را دور نمی‌زند |
| سرمایه‌گذار بازارچه | نتیجهٔ مجاز برای نمایش را می‌بیند | دادهٔ خام محرمانهٔ بانک را نمی‌بیند مگر سیاست شریک بگوید |
| بانک شریک | در صورت نیاز کانال استعلام | تسویه در این کارت |
| صندوق شریک | ممکن است استعلام را شرط خرید بداند | اجرای استعلام به‌جای بانک اگر کانال بانک است |
| پلتفرم | فراخوانی، کش کوتاه، نمایش محدود، audit | ظهرنویسی |

## ۴. نیازمندی‌ها و پیش‌نیازها

- محصولی: ایجاد آگهی و moderation موجود.
- فنی: `doion.checks`، یکتا بودن `(issuer, bank_name, cheque_serial_number)`.
- شریک: قرارداد دسترسی استعلام؛ اگر API رسمی نباشد، این قابلیت `blocked` است. کاندید B2B: [`vendor-landscape.md`](../../vendor-landscape.md) بخش ۲.۵.
- NFR: عدم ذخیرهٔ بیش از نیاز پاسخ استعلام؛ نرخ فراخوانی محدود.

## ۵. جای این قابلیت روی محصول فعلی

اعتبارسنجی اضافی روی `POST /api/v1/listings/`. UI ویزارد ثبت آگهی. وضعیت آگهی همان ماشین‌حالت فعلی است با کد رد جدید.

## ۶. سناریو

### کاربر

دارنده آگهی می‌سازد؛ اگر استعلام ناسازگار باشد خطا/رد مشخص می‌بیند. سرمایه‌گذار روی آگهی منتشرشده نشان وضعیت مجاز را می‌بیند.

### پلتفرم

قبل از `pending_moderation` یا هنگام moderation استعلام می‌زند؛ نتیجه را به تصمیم ناظر ضمیمه می‌کند.

### سناریوهای شکست

API صیاد/بانک timeout → آگهی در صف ناظر با برچسب «استعلام ناموفق» می‌ماند؛ انتشار خودکار نمی‌شود.

## ۷. شرایط پذیرش

- [ ] استعلام موفق ناسازگار مانع انتشار بدون تصمیم ناظر است.
- [ ] پلتفرم هیچ endpoint ظهرنویسی یا انتقال مالکیت ندارد.
- [ ] با فلگ خاموش، ثبت آگهی لایه ۱ بدون استعلام زنده کار می‌کند.

## ۸. رول‌اوت و کنترل

فلگ `sayad_inquiry_enabled`. خاموش = رفتار فعلی. قطع کانال = فقط moderation دستی.
