# Feature Specification — کاتالوگ بانک و نشان بانک

## 1. Feature Overview

چک‌یار امروز بانک را فقط به‌صورت متن آزاد روی آگهی نگه می‌دارد و در UI کنار نام بانک یک آیکون عمومی ساختمان نشان می‌دهد. این ویژگی بانک را به یک موجودیت مشخص تبدیل می‌کند: هر آگهی باید به یکی از بانک‌های کاتالوگ وصل باشد؛ کاتالوگ (کد، نام نمایشی، نام‌های معادل، لوگو در صورت وجود، رنگ برند روشن و تیره) برای مهمان و کاربر واردشده از API عمومی خوانده می‌شود؛ و در هر جایی که نام بانک دیده می‌شود، همان نشان بانک (لوگو یا حرف اول + رنگ برند) نمایش داده می‌شود. تا زمان فایل رسمی لوگو، حرف اول نام نمایشی روی پس‌زمینهٔ رنگ برند کافی است. تعریف بانک و آپلود لوگو فقط از ادمین جنگو انجام می‌شود.

- **Scope:** FULL-STACK
- **Capability types:** UI FEATURE · API / SERVICE · DATA LAYER
- **مخاطبان انسانی:** مهمان لندینگ، دارنده چک، سرمایه‌گذار، ناظر، ادمین جنگو
- **مصرف‌کنندگان سیستمی:** UI فعال (`checkyar-googleai`)، کلاینت‌های فعلی listings/marketplace/matches/moderation، دستور seed دمو، ادمین جنگو
- **ریپوی اجرا:** بک‌اند و قرارداد API در `doion`؛ UI فقط از مسیر Google AI Studio (همگام‌سازی یک‌طرفه)

## 2. Surfaces & Contract

### 2.1 UI

نشان بانک در **همه** سطوحی که امروز نام بانک دیده می‌شود اجباری است، از جمله:

| سطح | تعامل مرتبط |
|-----|-------------|
| لندینگ: پیش‌نمایش هیرو و کارت آگهی زنده | نمایش فقط؛ کلیک طبق رفتار فعلی لندینگ |
| بازارچه: کارت آگهی، جدول، ویجت جدیدترین‌ها | نمایش؛ فیلتر بانک با لوگو داخل گزینه |
| جزئیات آگهی | نمایش |
| ثبت و ویرایش آگهی | انتخاب فقط از کاتالوگ؛ هر گزینه لوگو/حرف‌اول + نام |
| آگهی‌های من، مچ‌ها، جزئیات معامله | نمایش |
| صف moderation و جزئیات بررسی | نمایش |
| گزارش‌ها: فیلتر بانک | انتخاب از کاتالوگ با لوگو داخل گزینه |
| حساب کاربری: بانک مقصد واریز | انتخاب فقط از کاتالوگ با نشان بانک داخل گزینه؛ متن آزاد حذف می‌شود |
| ادمین جنگو: بانک | ایجاد/ویرایش بانک، آپلود لوگو، تنظیم رنگ‌ها و نام‌های معادل (فقط Live؛ در mock وجود ندارد) |

**تعامل‌ها**

- فیلتر بازارچه و گزارش: کاربر یک بانک از کاتالوگ انتخاب می‌کند یا گزینهٔ «همه بانک‌ها» را می‌گذارد.
- ثبت/ویرایش آگهی: کاربر باید یک بانک از کاتالوگ انتخاب کند؛ ارسال بدون بانک یا با متن آزاد نامعتبر است و API صدا زده نمی‌شود تا مقدار معتبر انتخاب شود.
- دراپ‌داون‌ها: هر گزینهٔ بانک نشان بانک + نام نمایشی دارد.

**حالت‌های بصری نشان بانک**

| حالت | نمایش |
|------|--------|
| بانک کاتالوگ با لوگو | تصویر لوگو کنار نام نمایشی |
| بانک کاتالوگ بدون لوگو | حرف اول نام نمایشی روی سطح رنگی برند (جفت روشن/تیره متناسب با تم فعلی صفحه) + نام نمایشی |
| بانک ناشناس / بدون تطبیق کاتالوگ | آیکون ساختمان فعلی + حرف اول همان متن ذخیره‌شده؛ رنگ برند کاتالوگ اعمال نمی‌شود |
| «همه بانک‌ها» | متن «همه بانک‌ها» + آیکون ساختمان عمومی؛ بدون رنگ/لوگوی هیچ بانک مشخص |
| کاتالوگ در حال بارگذاری (فرم/فیلتر) | کنترل انتخاب بانک غیرفعال است و حالت loading دیده می‌شود؛ کارت‌هایی که از قبل `bank` تو در تو دارند نشان را بدون انتظار کاتالوگ نشان می‌دهند |
| کاتالوگ خالی از API | فرم/فیلتر بانک خالی است و انتخاب بانک ممکن نیست؛ ثبت آگهی ارسال نمی‌شود |
| شکست API کاتالوگ | UI به کاتالوگ محلی هم‌مجموعه برمی‌گردد و نشان بانک را از آن می‌سازد؛ خطای مسدودکننده تمام‌صفحه نشان داده نمی‌شود |
| مهمان در لندینگ | همان نشان بانک؛ لوگو فقط از فایل/آدرس خود محصول است، نه CDN خارجی بانک‌ها |

تم فعلی محصول تیره است؛ رنگ `brand_color_dark` برای پس‌زمینه/سطح نشان در تم تیره و `brand_color_light` برای تم روشن استفاده می‌شود.

### 2.2 API / events

#### A) فهرست کاتالوگ بانک (عمومی)

- **Method / path:** `GET /api/v1/banks/`
- **Auth:** AllowAny (مهمان و کاربر واردشده)
- **Write از این API وجود ندارد.** ایجاد/ویرایش/آپلود لوگو فقط از ادمین جنگو است.

**Response 200:** آرایهٔ بانک‌های فعال. ترتیب پایدار است (بر اساس نام نمایشی صعودی).

```json
[
  {
    "code": "mellat",
    "display_name": "بانک ملت",
    "aliases": ["بانک ملت", "ملت"],
    "logo_url": null,
    "brand_color_light": "#E21836",
    "brand_color_dark": "#C4112C"
  }
]
```

| Field | Type | Meaning |
|-------|------|---------|
| `code` | string | شناسه پایدار و یکتای بانک برای کلاینت و فیلتر |
| `display_name` | string | نام نمایشی رسمی در UI |
| `aliases` | string[] | نام‌های معادل برای تطبیق داده‌های قدیمی؛ شامل خود `display_name` |
| `logo_url` | string \| null | آدرس عمومی فایل لوگو؛ `null` یعنی لوگو هنوز آپلود نشده |
| `brand_color_light` | string | رنگ برند برای تم روشن؛ فرمت `#RRGGBB` |
| `brand_color_dark` | string | رنگ برند برای تم تیره؛ فرمت `#RRGGBB` |

**خطا:** این endpoint برای درخواست معتبر همیشه 200 می‌دهد. اگر کاتالوگ خالی باشد، بدنه `[]` است نه خطا.

#### B) خواندن آگهی / بازارچه / مچ / moderation (additive)

هر پاسخ آگهی که امروز `bank_name` دارد، علاوه بر آن یک شیء `bank` تو در تو دارد. `bank_name` برابر `display_name` بانک وصل‌شده باقی می‌ماند تا کلاینت‌های فعلی نشکند.

شیء `bank` در پاسخ:

| Field | Type | Meaning |
|-------|------|---------|
| `code` | string | کد بانک کاتالوگ |
| `display_name` | string | نام نمایشی |
| `logo_url` | string \| null | لوگو یا null |
| `brand_color_light` | string | `#RRGGBB` |
| `brand_color_dark` | string | `#RRGGBB` |

`aliases` در پاسخ آگهی نمی‌آید.

این شکل روی همهٔ پاسخ‌هایی که امروز `bank_name` آگهی را برمی‌گردانند اعمال می‌شود، از جمله: create/retrieve/list listing، marketplace list، marketplace latest (عمومی)، listing خلاصه داخل match، آیتم moderation.

#### C) ایجاد و ویرایش آگهی (breaking برای ورودی)

- **Create:** `POST /api/v1/listings/`
- **Update:** `PATCH` / `PUT` همان مسیر فعلی ویرایش آگهی
- **Auth:** بدون تغییر نسبت به قرارداد فعلی آگهی (IsAuthenticated + KYC مصوب برای ایجاد)

**ورودی بانک:** فیلد اجباری `bank` از نوع string = `code` بانک فعال کاتالوگ.

ارسال `bank_name` به‌عنوان جایگزین `bank` رد می‌شود.

**خطاها (هم‌خانواده VALIDATION_ERROR / 400 فعلی):**

| شرط | نتیجه |
|-----|--------|
| `bank` نیست یا خالی است | 400؛ آگهی ذخیره نمی‌شود |
| `bank` با هیچ کد فعال کاتالوگ برابر نیست | 400؛ آگهی ذخیره نمی‌شود |
| `bank_name` بدون `bank` معتبر | 400؛ آگهی ذخیره نمی‌شود |

#### D) فیلتر بازارچه

- پارامتر فعلی `bank_name` (جزئی روی نام) همچنان کار می‌کند و روی `display_name` و aliases بانک وصل‌شده تطبیق می‌دهد.
- پارامتر جدید `bank` (دقیق روی `code`) اضافه می‌شود. اگر هر دو آمده باشند، `bank` (کد) مقدم است.

#### E) ادمین جنگو (نه REST)

کاربر staff/superuser جنگو می‌تواند بانک را ایجاد و ویرایش کند، لوگو آپلود کند، رنگ‌ها و aliases و فعال/غیرفعال را تغییر دهد. هیچ endpoint REST برای mutation بانک در این فاز وجود ندارد.

### 2.3 Inputs & outputs

**ورودی کاتالوگ (ادمین جنگو)**

| Name | Type | Required | Constraints |
|------|------|----------|-------------|
| code | string | Yes | یکتا، غیرخالی، پایدار پس از ایجاد |
| display_name | string | Yes | غیرخالی |
| aliases | list of strings | Yes | حداقل شامل display_name؛ هر alias در کل کاتالوگ یکتا است |
| logo | file | No | تصویر؛ نبودن آن یعنی `logo_url` برابر null |
| brand_color_light | string | Yes | `#RRGGBB` |
| brand_color_dark | string | Yes | `#RRGGBB` |
| is_active | boolean | Yes | بانک غیرفعال در GET کاتالوگ و انتخاب ایجاد آگهی نمی‌آید |

**ورودی ایجاد/ویرایش آگهی (بانک)**

| Name | Type | Required | Constraints |
|------|------|----------|-------------|
| bank | string | Yes | باید `code` یک بانک فعال باشد |

**ورودی حساب بانکی / واریز (UI)**

| Name | Type | Required | Constraints |
|------|------|----------|-------------|
| bank | string | Yes برای ذخیره تنظیم | `code` یک بانک فعال کاتالوگ |

در این فاز قرارداد REST جدا برای «بانک مقصد واریز» اضافه نمی‌شود. مقدار انتخاب‌شده در mock داخل شبیه‌ساز ذخیره می‌شود و در Live روی همین صفحه در state همان جلسه می‌ماند (رفتار ذخیره‌سازی فعلی صفحه حفظ می‌شود، فقط کنترل از متن آزاد به انتخاب کاتالوگ عوض می‌شود).

**خروجی نشان بانک در UI**

- نام نمایشی بانک
- لوگو اگر `logo_url` غیر null باشد؛ وگرنه حرف اول `display_name`
- رنگ سطح نشان از جفت روشن/تیره متناسب با تم

## 3. Business Rules

1. هر آگهی جدید یا ویرایش‌شده دقیقاً به یک بانک فعال کاتالوگ وصل است؛ متن آزاد به‌عنوان بانک پذیرفته نمی‌شود.
2. کاتالوگ اولیه دقیقاً اتحاد بانک‌های امروز هاردکد در UI و seed دمو است (جدول بخش ۳.۱)؛ بانک جدید خارج از این فهرست در این فاز از طریق محصول اضافه نمی‌شود مگر ادمین جنگو آن را تعریف کند.
3. `code` بانک در کل سیستم یکتا است و پس از ایجاد تغییر نمی‌کند.
4. هر `alias` حداکثر به یک بانک تعلق دارد؛ دو بانک نمی‌توانند alias یکسان داشته باشند.
5. `GET /api/v1/banks/` بدون احراز هویت 200 و فهرست بانک‌های فعال را برمی‌گرداند.
6. کاربر غیر staff نمی‌تواند از API بانک بسازد یا ویرایش کند؛ تلاش REST برای ایجاد/ویرایش بانک یا 404 است یا 405 (این فاز آن مسیر را ندارد).
7. فقط staff/superuser جنگو بانک را می‌سازد/ویرایش می‌کند و لوگو آپلود می‌کند.
8. اگر لوگو نباشد، پاسخ `logo_url` برابر `null` است و UI حرف اول + رنگ برند را نشان می‌دهد.
9. رنگ‌های برند در پاسخ همیشه دو مقدار `#RRGGBB` هستند (روشن و تیره).
10. در پاسخ آگهی، `bank_name` همیشه برابر `display_name` بانک وصل‌شده است.
11. پس از مهاجرت داده، هر آگهی موجود که `bank_name` آن با `display_name` یا یکی از aliases یک بانک برابر است (بدون حساسیت به فاصلهٔ ابتدا/انتها) به همان بانک وصل می‌شود.
12. آگهی موجود که به هیچ بانک کاتالوگ نگاشت نشود مهاجرت را fail نمی‌کند؛ `bank` در پاسخ `null` می‌ماند و UI حالت ناشناس را نشان می‌دهد (آیکون ساختمان فعلی + حرف اول متن ذخیره‌شده؛ بدون رنگ برند کاتالوگ). ایجاد/ویرایش جدید همچنان بدون بانک معتبر 400 است.
13. انتخاب بانک در ایجاد/ویرایش آگهی فقط از کاتالوگ فعال است؛ گزینهٔ متن آزاد وجود ندارد.
14. فیلتر «همه بانک‌ها» یعنی هیچ قید بانکی روی فهرست اعمال نمی‌شود.
15. مهمان لندینگ نشان بانک را از داده‌های `bank` تو در تو در `GET /api/v1/marketplace/listings/latest/` می‌بیند و برای فیلتر/فرم به `GET /api/v1/banks/` نیاز دارد.
16. گزینهٔ «همه بانک‌ها» متن «همه بانک‌ها» به‌همراه آیکون ساختمان عمومی است؛ لوگوی هیچ بانک مشخص و رنگ برند هیچ بانکی روی آن اعمال نمی‌شود.
17. منبع کاتالوگ در کلاینت به حالت اجرا بستگی دارد (بخش ۳.۲). پس از دردسترس بودن API، منبع حقیقت کاتالوگ برای Live همان API است و کاتالوگ محلی فقط fallback هنگام شکست شبکه است.
18. لوگو از CDN یا دامنهٔ بانک‌های ثالث بارگذاری نمی‌شود؛ فقط آدرس فایل خود محصول (`logo_url` کاتالوگ) مجاز است.
19. بانک غیرفعال در کاتالوگ عمومی و در انتخاب ایجاد آگهی نیست؛ آگهی از قبل وصل‌شده به آن بانک همچنان `bank` را در پاسخ می‌آورد تا نشان نمایش داده شود.
20. یکتایی فعلی «صادرکننده + بانک + سریال چک» بر اساس بانک کاتالوگ (نه متن آزاد) اعمال می‌شود.

### 3.1 فهرست اولیه بانک‌ها (نام نمایشی + aliases الزامی)

| display_name | aliases الزامی (حداقل) |
|--------------|-------------------------|
| بانک ملت | بانک ملت |
| بانک ملی ایران | بانک ملی ایران، بانک ملی |
| بانک صادرات ایران | بانک صادرات ایران، بانک صادرات |
| بانک پاسارگاد | بانک پاسارگاد |
| بانک تجارت | بانک تجارت |
| بانک سامان | بانک سامان |
| بانک پارسیان | بانک پارسیان |
| بانک سپه | بانک سپه |
| بانک آینده | بانک آینده |
| بانک مسکن | بانک مسکن |
| بانک شهر | بانک شهر |
| بانک کشاورزی | بانک کشاورزی |
| بانک رفاه کارگران | بانک رفاه کارگران |
| بانک سینا | بانک سینا |

`code` پایدار لاتین برای هر ردیف در پیاده‌سازی تعیین می‌شود ولی در رفتار تست‌پذیر باید یکتا و غیرخالی باشد.

جفت `#RRGGBB` در seed تقریبی و متمایز است؛ هویت بصری رسمی برند قفل نمی‌شود. ادمین جنگو می‌تواند رنگ را بعداً اصلاح کند. تست‌ها فقط معتبر بودن فرمت `#RRGGBB` و غیرخالی بودن هر دو رنگ را قفل می‌کنند.

### 3.2 Mock و شبیه‌ساز

21. وقتی `VITE_USE_MOCK=true` و mock روشن است، هیچ درخواست HTTP برای کاتالوگ یا آگهی به Django زده نمی‌شود؛ همان لایه `*Api` فعلی به شبیه‌ساز (`useBackendSimulatorStore`) می‌رود.
22. شبیه‌ساز همان ۱۴ بانک بخش ۳.۱ را با همان شکل پاسخ `GET /api/v1/banks/` در حافظه دارد (`logo_url` در seed شبیه‌ساز `null` است مگر صریحاً مقدار داده شود).
23. پاسخ‌های آگهی/بازارچه/مچ/moderation شبیه‌ساز همان شیء `bank` تو در تو (یا `null`) و `bank_name` نمایشی را برمی‌گردانند که قرارداد Live دارد.
24. `createListing` / `updateListing` در شبیه‌ساز فیلد `bank` (کد) را اجباری می‌کنند؛ `bank_name` تنها رد می‌شود؛ کد نامعتبر همان خطای اعتبارسنجی کلاینتی/شبیه‌ساز را می‌دهد که UI برای 400 Live نشان می‌دهد.
25. فیلتر بازارچه شبیه‌ساز پارامتر `bank` (کد دقیق) و `bank_name` (جزئی روی نام/alias) را مثل Live اعمال می‌کند.
26. کاتالوگ ۱۴ بانک در کلاینت یک منبع واحد است: seed شبیه‌ساز، fallback Live، و lookup نشان بانک از همان مجموعه خوانده می‌شوند؛ فهرست جدا در هر فرم تکرار نمی‌شود.
27. در mock، ادمین جنگو و آپلود لوگو در دسترس نیست؛ نمی‌توان از UI محصول بانک جدید ساخت یا لوگو آپلود کرد.
28. وقتی `VITE_USE_MOCK=false` (Live): اگر `GET /api/v1/banks/` موفق باشد همان پاسخ سرور استفاده می‌شود؛ اگر شکست بخورد یا هنوز پیاده نشده باشد، UI از همان کاتالوگ محلی ۱۴ بانک استفاده می‌کند و صفحه را مسدود نمی‌کند.
29. فیلد «بانک مقصد واریز» در mock کد بانک انتخاب‌شده را در شبیه‌ساز نگه می‌دارد؛ در Live بدون قرارداد پروفایل جدید، انتخاب در state همان صفحه می‌ماند.

## 4. Acceptance Scenarios

**Scenario 1: مهمان کاتالوگ را می‌خواند**
- Given: کاتالوگ seed شده و سرور در دسترس است
- When: مهمان بدون توکن `GET /api/v1/banks/` می‌زند
- Then: 200 با آرایه‌ای که حداقل ۱۴ بانک بخش ۳.۱ را با `code`، `display_name`، `aliases`، `logo_url`، `brand_color_light`، `brand_color_dark` دارد

**Scenario 2: مهمان لندینگ نشان بانک را می‌بیند**
- Given: حداقل یک آگهی published به بانک ملت وصل است و لوگو null است
- When: مهمان لندینگ را باز می‌کند
- Then: کنار نام «بانک ملت» حرف اول آن نام روی رنگ `brand_color_dark` (تم تیره) دیده می‌شود و درخواستی به دامنهٔ خارجی بانک زده نمی‌شود

**Scenario 3: کارت بازارچه با لوگو**
- Given: برای بانک ملت `logo_url` غیر null است و آگهی published به آن وصل است
- When: کاربر واردشده بازارچه را باز می‌کند
- Then: کارت آگهی تصویر لوگو را کنار نام نمایشی نشان می‌دهد نه آیکون ساختمان عمومی

**Scenario 4: ایجاد آگهی با کد معتبر**
- Given: کاربر با KYC مصوب لاگین است و `mellat` در کاتالوگ فعال است
- When: `POST /api/v1/listings/` با `bank: "mellat"` و بقیه فیلدهای معتبر ارسال می‌شود
- Then: 201؛ پاسخ شامل `bank.code == "mellat"` و `bank_name == "بانک ملت"` است

**Scenario 5: ایجاد آگهی با متن آزاد رد می‌شود**
- Given: همان کاربر معتبر
- When: `POST /api/v1/listings/` با `bank_name: "بانک ملت"` و بدون `bank` ارسال می‌شود
- Then: 400 VALIDATION_ERROR؛ آگهی ایجاد نمی‌شود

**Scenario 6: ایجاد آگهی با کد نامعتبر رد می‌شود**
- Given: همان کاربر معتبر
- When: `POST` با `bank: "not-a-bank"` ارسال می‌شود
- Then: 400؛ آگهی ایجاد نمی‌شود

**Scenario 7: انتخاب بانک در فرم UI**
- Given: کاتالوگ در UI در دسترس است (API یا محلی)
- When: کاربر فرم ثبت آگهی را باز می‌کند و بانک را خالی می‌گذارد و submit می‌کند
- Then: خطای فیلد بانک نمایش داده می‌شود و درخواست create ارسال نمی‌شود

**Scenario 8: دراپ‌داون فیلتر بازارچه لوگودار است**
- Given: کاتالوگ در UI در دسترس است
- When: کاربر فیلتر بانک بازارچه را باز می‌کند
- Then: هر گزینهٔ بانک نشان بانک + نام نمایشی دارد و گزینهٔ «همه بانک‌ها» متن به‌همراه آیکون ساختمان عمومی است، بدون لوگو یا رنگ هیچ بانک مشخص

**Scenario 9: فیلتر با کد بانک**
- Given: آگهی‌های published از ملت و تجارت وجود دارد
- When: `GET /api/v1/marketplace/listings/?bank=mellat`
- Then: 200؛ همهٔ results دارای `bank.code == "mellat"` هستند و آگهی تجارت در results نیست

**Scenario 10: فیلتر قدیمی bank_name با alias**
- Given: آگهی به «بانک ملی ایران» وصل است
- When: `GET /api/v1/marketplace/listings/?bank_name=ملی`
- Then: 200؛ آن آگهی در results هست

**Scenario 11: مهاجرت alias**
- Given: آگهی قدیمی با `bank_name` برابر «بانک ملی» وجود دارد
- When: مهاجرت/بک‌فیل این ویژگی اجرا می‌شود
- Then: همان آگهی به بانک با display_name «بانک ملی ایران» وصل است و پاسخ retrieve مقدار `bank_name` را «بانک ملی ایران» برمی‌گرداند

**Scenario 12: بانک ناشناس در UI**
- Given: یک آگهی با `bank: null` (نگاشت‌نشده) به کلاینت می‌رسد
- When: کارت/جزئیات آن آگهی رندر می‌شود
- Then: آیکون ساختمان فعلی و حرف اول `bank_name` موجود دیده می‌شود و رنگ برند کاتالوگ اعمال نمی‌شود

**Scenario 13: شکست کاتالوگ API در UI**
- Given: `GET /api/v1/banks/` شکست می‌خورد و کاتالوگ محلی موجود است
- When: کاربر فرم ثبت یا فیلتر بازارچه را باز می‌کند
- Then: گزینه‌های بانک از کاتالوگ محلی همان مجموعهٔ ۳.۱ پر می‌شوند و صفحه خطای تمام‌صفحه نمی‌شود

**Scenario 14: کاتالوگ خالی**
- Given: هیچ بانک فعالی وجود ندارد
- When: کاربر فرم ثبت آگهی را باز می‌کند
- Then: انتخاب بانک خالی است و submit ایجاد آگهی انجام نمی‌شود

**Scenario 15: مهمان نمی‌تواند بانک بسازد**
- Given: مهمان بدون توکن
- When: هر درخواست mutating به مسیر بانک‌ها (اگر وجود داشته باشد) یا مسیر غیرمستند
- Then: بانک جدید ساخته نمی‌شود؛ کاتالوگ GET همچنان فقط خواندنی است

**Scenario 16: ادمین لوگو آپلود می‌کند**
- Given: کاربر staff جنگو و بانک ملت بدون لوگو
- When: از ادمین جنگو فایل لوگو برای آن بانک ذخیره می‌شود
- Then: `GET /api/v1/banks/` برای آن بانک `logo_url` غیر null برمی‌گرداند و کارت‌ها تصویر را نشان می‌دهند

**Scenario 17: بانک غیرفعال در انتخاب نیست**
- Given: بانکی در ادمین غیرفعال شده است
- When: `GET /api/v1/banks/` و فرم ایجاد آگهی
- Then: آن بانک در فهرست انتخاب نیست؛ POST با `code` آن 400 است

**Scenario 18: آگهی از قبل وصل به بانک غیرفعال هنوز نشان دارد**
- Given: آگهی published به بانکی وصل است که بعداً غیرفعال شده
- When: retrieve/marketplace آن آگهی خوانده می‌شود
- Then: شیء `bank` هنوز با code و رنگ/لوگوی همان بانک برمی‌گردد

**Scenario 19: یکتایی سریال در همان بانک**
- Given: آگهی با issuer A، بانک mellat، سریال S موجود است
- When: همان کاربر آگهی دیگری با همان issuer و `bank: "mellat"` و همان سریال می‌سازد
- Then: 400؛ تکراری رد می‌شود

**Scenario 20: mock بدون HTTP به Django**
- Given: `VITE_USE_MOCK=true` و mock روشن است
- When: بازارچه، فرم ثبت، لندینگ، یا حساب بانکی باز می‌شود
- Then: نشان بانک و گزینه‌ها از کاتالوگ شبیه‌ساز مجموعهٔ ۳.۱ کار می‌کنند و درخواستی به `/api/v1/banks/` شبکه زده نمی‌شود

**Scenario 22: ساخت آگهی در mock با کد بانک**
- Given: mock روشن است و کاربر seedشده لاگین است
- When: ایجاد آگهی با `bank: "mellat"` انجام می‌شود
- Then: آگهی در شبیه‌ساز ذخیره می‌شود، پاسخ `bank.code == "mellat"` و `bank_name == "بانک ملت"` دارد، و کارت همان نشان بانک را نشان می‌دهد

**Scenario 23: بانک مقصد واریز از کاتالوگ**
- Given: صفحه حساب بانکی باز است و کاتالوگ در دسترس است
- When: کاربر به‌جای تایپ متن، یک بانک کاتالوگ را انتخاب می‌کند
- Then: فیلد دیگر `NInput` متن آزاد نیست؛ نشان بانک + نام نمایشی دیده می‌شود و مقدار ذخیره‌شده `code` آن بانک است

**Scenario 21: تم روشن/تیره**
- Given: بانک با دو رنگ متفاوت light/dark و بدون لوگو
- When: UI در تم تیره (پیش‌فرض محصول) کارت را نشان می‌دهد
- Then: پس‌زمینهٔ حرف اول از `brand_color_dark` است نه `brand_color_light`

## 5. Out of Scope

- همگام‌سازی با بانک مرکزی / لیست رسمی کامل بانک‌های ایران
- اعتبارسنجی شبا، کد پیش‌شماره حساب، یا درستی لوگوی حقوقی برند
- REST API ادمین برای CRUD بانک (فقط ادمین جنگو)
- پنل ادمین داخل Vue برای مدیریت بانک
- اجازهٔ متن آزاد بانک در ایجاد/ویرایش آگهی پس از این ویژگی
- بارگذاری لوگو از CDN یا وب‌سایت بانک‌ها
- تغییر نقش‌ها، KYC، یا permissionهای فعلی آگهی به‌جز ورودی بانک
- طراحی هویت بصری قطعی جفت رنگ رسمی هر بانک (seed تقریبی کافی است)
- REST/مدل پروفایل برای ماندگار کردن «بانک مقصد واریز» در Django (فقط کنترل UI کاتالوگ در این فاز)
- آپلود لوگو یا CRUD بانک داخل mock / شبیه‌ساز

## 6. Decisions already resolved (from clarification)

| موضوع | تصمیم |
|--------|--------|
| Scope | FULL-STACK |
| خواندن کاتالوگ | عمومی؛ مهمان هم از API |
| فهرست اولیه | فقط اتحاد بانک‌های هاردکد فعلی |
| فیلدها | code، display_name، aliases، logo، رنگ روشن/تیره |
| لوگو تا فایل رسمی | حرف اول + رنگ برند |
| اتصال آگهی | FK/ارتباط اجباری به بانک کاتالوگ |
| انتخاب در فرم | فقط کاتالوگ |
| نوشتن کاتالوگ | ادمین جنگو + آپلود لوگو؛ نه API ادمین |
| قرارداد خواندن آگهی | `bank` تو در تو + حفظ `bank_name` نمایشی (بهینه برای کارت‌ها بدون join کلاینتی) + GET جداگانه کاتالوگ برای فرم/فیلتر |
| تحویل UI | کاتالوگ محلی تا آماده شدن API؛ بعد API با fallback محلی |
| پوشش UI | همه‌جا که نام بانک هست، از جمله دراپ‌داون‌ها و لندینگ |
| لندینگ | نشان بانک مجاز است اگر فایل/آدرس خود محصول باشد؛ CDN بانک ممنوع |
| آگهی بدون نگاشت | `bank: null` مجاز؛ UI ناشناس (ساختمان + حرف اول) |
| «همه بانک‌ها» | متن + آیکون ساختمان عمومی |
| رنگ seed | `#RRGGBB` تقریبی؛ ادمین بعداً اصلاح می‌کند |
| حساب بانکی / واریز | انتخاب از کاتالوگ در همین فاز؛ بدون API پروفایل جدید |
| Mock | شبیه‌ساز همان قرارداد را برمی‌گرداند؛ بدون HTTP؛ بدون ادمین جنگو |
